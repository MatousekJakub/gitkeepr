# GitKeepr v0.2.0

## Summary

GitKeepr v0.2.0 changes the project from an ambient autonomous PR loop into an explicitly triggered, bounded PR finalization worker designed to sit underneath ChatGPT/human supervision.

## Changes

- Run GitKeepr only from an exact trusted `/gitkeepr run` PR comment or manual `workflow_dispatch`; ordinary PR opens, pushes, reviews, and comments no longer start agent work.
- Default finalization budget is two Build -> Review cycles through `GITKEEPR_FINALIZATION_CYCLES`.
- Build now treats the PR as an existing implementation to finalize and resolves all safely actionable remaining work in each turn instead of one planned task at a time.
- Review `PASS` produces `gitkeepr:ready`; exhausting the bounded cycle budget with unresolved work produces `gitkeepr:needs-supervisor` as a normal successful checkpoint.
- External PR-head changes supersede stale workers instead of triggering rebase/merge behavior or allowing stale state publication.
- Credentialed branch pushes use an exact expected-HEAD lease so a concurrent branch update cannot be overwritten between a HEAD check and push.
- Remove the v0.1 external-helper, `gitkeepr:no-build`, direct-reply, transient building/reviewing, waiting-human, blocked, and no-progress orchestration protocols.
- Keep trusted human and Copilot discussion as context without letting that discussion implicitly trigger work.
- Preserve GitHub App token refresh/retry, agent credential isolation, workflow-owned Git operations, Context7, and Chrome DevTools MCP support.
- Keep existing healthy self-hosted runners reusable across the upgrade.

## Upgrade

This release supersedes `v0.1.1`.

Install the newer CLI, then run `gitkeepr init` in each managed private repository to review and explicitly replace its release-pinned caller. v0.2 introduces `GITKEEPR_FINALIZATION_CYCLES` (default `2`); the old v0.1 `GITKEEPR_MAX_CYCLES` value is ignored by the v0.2 reusable workflow.

Existing healthy repository runners do not need to be re-registered solely because the GitKeepr release changed. Run `gitkeepr doctor` and `gitkeepr server doctor` after upgrading.
