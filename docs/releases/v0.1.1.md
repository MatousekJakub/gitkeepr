# GitKeepr v0.1.1

## Summary

GitKeepr v0.1.1 is a maintenance release that makes release preparation deterministic and fixes Build/Review loop state handling discovered while exercising the new release workflow.

## Changes

- Add deterministic, rollback-safe release preparation tooling that keeps `VERSION`, the CLI, installer, caller template, and release notes synchronized.
- Harden post-merge publishing so releases are created only from a clean checkout exactly matching the fetched `origin/main`, with the release tag verified at that exact commit.
- Give newly discovered Review `CONTINUE` feedback a Build opportunity before no-progress protection can stop the loop.
- Block no-progress only when the same unresolved `CONTINUE` is repeated on the same HEAD after Build has already received it.
- Preserve unresolved Review state across comment-only replies instead of incorrectly switching to `gitkeepr:waiting-human`.
- Require GitKeepr bot provenance for persisted Review markers and distinguish Review records from direct-reply system comments.
- Expand workflow contract coverage for review provenance, state transitions, and no-progress behavior.
- Fix the PR-loop shell syntax regression exposed after #6 and add a regression check that validates the rendered Build/Review shell block with `bash -n`.

## Upgrade

This release supersedes `v0.1.0`. Installing the newer release updates the CLI.
Run `gitkeepr init` in each managed private repository to review and explicitly
update its release-pinned caller to `v0.1.1`. Existing healthy repository runners
do not need to be re-registered solely because the GitKeepr release changed.
